

	- 고급 언어 => 개발자가 읽기 쉬움
	- 저급 언어 => 컴퓨터가 읽기 쉬움

	- 저급 언어 
		- 기계어
			- 명령어 : 0과 1로 이루어진 언어

		- 어셈블리어 
			- 기계어를 읽기 편한 형태로 번역한 언어
				ex) push, mov => 명령어 


	- 고급 언어 
		- C, C++, JAVA등
		- 컴파일 언어 --> 저급언어
			- 소스코드 --> 컴파일러 --> 목적코드
			- 전체를 훑어봄 
				=> 오류가 있는지 없는지 검사

			- 오류가 있으면 전체 실행x


		- 인터프리터 언어
			- 한줄씩 실행
			- 기다릴 필요 없음
			- 오류가 있으면 오류 전까지 실행

명령어의 구조
	- 명령어 : 연산코드 & 오퍼랜드 구조
		- 연산코드 : 수행할 연산
			ex) mov, push, pop 등등
		- 오퍼렌드 : 연산에 사용될 데이터 또는 데이터 위치
			ex) rbp, rsp, DWORD PTR
			- 주소필드
				- [오퍼랜드 필드] 라고도 함
				- 데이터보다 훨씬 더 많이 저장됨
				- 데이터가 저장된 위치를 훨씬 자주사용하게 됨
					=> 주소로 호출하게되면 훨씬 더 많은 값을 저장할 수 있기 때문이다.
		- 보통 연산코드에 오퍼랜드가 붙는데 없을수도 있음 [0-주소 명령어]

	- 연산코드
		- 데이터 전송
			ex) MOVE, STORE, LOAD, PUSH, POP
		- 산술/논리 연산
			ex) ADD/SUBJECT/MUL/INCREMENT/DECREMENT/AND/OR/NOT/COMPARE
		- 제어 흐름 변경
			- 특정 실행 주소를 특정 위치로 점프해서 옮겨라
			ex) JUMP, CONDITIONAL JUMP/HALT
				- Call : 실행할 주소를 저장한채 특정 주소로 실행순서를 옮겨라
				- Return : 호출할 때 저장했던 실행주소로 돌아가라

		- 입출력 제어
			- READ / WRITE / START IO /TEST IO
		
		- 스택 
			- 한쪽 끝이 막혀있는 자료구조
			- 후입선출(Last in First Out)

		- 큐
			- 양쪽 끝이 뚫려있는 자료구조
			- 선인선출(First in First Out)

	- 유효주소
		- 연산에 사용할 데이터가 저장된 위치

	- 명령어 지정 주소 방식
	== 메모리부분 ==
		- 유효주소를 찾는 방법

		- 즉시 주소 지정 방식
			- 연산에 사용될 데이터를 오퍼랜드에 명시
			- 가장 간단한 형태
			- 사용할 데이터 크기가 작아질 수 있지만 빠름

		- 직접 주소 지정 방식
			- 오퍼랜드 필드에 유효 주소를 명식
			- 연사코드가 클수록 그만큼 유효주소가 줄어듬

		- 간접 주소 지정 방식
			- 오퍼랜드에 데이터가 담겨있는 주소를 참조할 주소를 담아둠
			- 느림

	== 레지스터 부분 ==
		- 레지스터 직접 주소 지정 방식
			- 레지스터에 담겨있는 데이터를 명시
			- CPU가 메모리를 참조하는것보다 훨씬빠름

		- 레지스터 간접 주소 지정 방식
			- 레지스터에 데이터를 참조할 주소를 담음
