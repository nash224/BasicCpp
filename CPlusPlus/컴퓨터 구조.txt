1. 컴퓨터를 알아야하는 이유
	- 보통 프로그래밍을 잘할려면 문법부터 알아야한다고 생각한다.
		=> 문법을 잘알면 프로그래밍을 한다고 생각하기 때문

	- 하지만 영상에서는 프로그래밍을 잘하기 위해서는 문법뿐만이 아닌 컴퓨터의 원리를 알아야한다고 주장한다.
		=> 컴퓨터의 근간이란 == 운영체제를 의미

	- 그럼 컴퓨터를 알면 뭐가 좋은가?
			=> 문제 해결능력 상승, 성능, 용량, 비용을 알게 된다.
			=> 내가 작성한 프로그래밍이 어떤 동작을 하는지 깊이 살표볼 필요가 있다.

	- 항상 적절한 비용에 적절한 성능을 고르는게 개발자 안목중 하나이다.




2. 컴퓨터 구조의 큰 그림
	- 컴퓨터 구조		- 컴퓨터가 이해해야하는 정보	
		- 데이터 : 숫자(가장 근본적인 컴퓨터 언어), 문자(수의 배열), 이미지(픽셀들의 조합)
		- 명령어 : 컴퓨터를 움직이는 정보(OS, Function)
			ex) 1에 2를 더해라 = {1,2} 데이터, {더해라} 명령어
		- 컴퓨터는 소스코드를 이해하는게 아니라 기계어로 변환해서 명령어로 읽는다.


					- 일반적으로 우리는 2진수나 16진수를 읽으며 이해하기 힘들다.
					- 그래서 컴퓨터는 조금 더 고수준의 언어로 변환하는데 
							=> 그걸 어셈블리어라고 한다. (컴퓨터가 이해하는 실질적인 명령어) 


					- 컴퓨터의 네가지 부품	
						- CPU
							- 메모리에 저장되어 있는 데이터와 명령어를 가져와 해석해서 실행한다.

							- ALU : 계산기 (회로) , {산술연산장치} 라고도 한다.
							- 레지스터 : CPU의 내부 저장장치
							- 제어장치 : 제어신호? 를 내보내고, 명령어를 실행하는 장치
								=> 제어신호란 메모리 읽기 및 쓰기 신호다.
									ex) 1번 장치에 저거랑 2번 장치에 저거 읽어와서 내 레지스터에 저장해
										그리고 이걸 해석해서 ALU가 대신 계산해줄꺼야
										이 계산된 값을 제어신호를 보내 메모리의 새로운 번지에 저장해라.

						- 메모리 (주기억장치)
							- !현재 실행되는! 프로그램의 명령어와 데이터를 저장한다.
							- 명령어와 데이터를 메모리에 저장하기 위해서는 어떤 위치정보가 저장되어 있어야한다.
								즉, 프로그램이 실행되려면 메모리에 저장되어 있어야한다.
							- 전원이 꺼지면 메모리에 저장된 내용을 잃는다 
								=> 휘발성이라고 한다.


						- 보조기억장치
							- ssd, hdd 
							- 프로그램이 꺼져도 내용을 저장하고 있다.

						- 입출력장치 
							- 컴퓨터 외부에 연결되어 컴퓨터와 정보교환을 할 수 있다.

					- 이외의 컴퓨터 부품
						- 메인보드
							- 각 컴퓨터 부품을 연결하는 판

						- 시스템 버스 
							- 버스를 통해 정보를 주고 받음
							- 각 핵심 부품을 연결하는 시스템 

							- 시스템 버스 내부 구성
								- 주소 버스 : 주소값 교환
								- 데이터 버스 : 데이터와 명령어 교환
								- 제어 버스 : 제어 신호 전달

								ex) CPU가 RAM에 있는 데이터를 읽을때
									=> 제어 신호 : 나 이 데이터 읽을래
									=> 주소 버스 : 데이터의 주소는?
									=> 데이터 버스 : 이 주소의 데이터는 이거야

								ex) CPU가 RAM에게 전보를 전달할 때
									=> 데이터 버스 : 이 데이터를 줄게
									=> 주소 버스 : 남는 주소가 저거네?
									=> 제어 신호 : 저기에 전달해!


3. 운영체제란?
	- 자원 : 시스템 리소스 
		=> 프로그램을 실행하기 위한 필요한 소스

	- 운영체제 : 자원(또는 !실행중인!{Process} 프로그램)을 관리하는 특별한 프로그램
	
	- 운영체제는 어디에 저장될까?
		=> RAM에 특별한 공간에 저장되어 있다.
			=> 이 공간을 커널 영역이라고 한다.

		- 그리고 이외의 영역에는 사용자가 사용하는 응용 프로그램이 있다.

	- 응용 프로그램을 실행시키면 누가 램에 할당해줄까?
		=> 특별한 메모리에 존재하는 운영체제가 자원을 할당해준다.
		=> 그리고 실행을 끝낸 응용 프로그램은 메모리에 지워준다.
			=> 이걸 메모리 관리라고 한다.

	- 만약 RAM에 있는 공간보다 더 큰 응용 프로그램을 실행시킬 수 있는가?
		=> Yes : 페이징과 스왑핑을 이용하여 실행시킬 수 있다.

	- 여러 응용 프로그램을 실행할 때, 어떻게 동시에 실행되는 걸까?
		=> 정말 빠른속도로 업데이트 돌려서 가능하게 한다.

	- 여러 응용 프로그램의 누가 먼저 실행(업데이트) 되야하는가?
		=> 운영체제가 결정해준다.
		=> 운영체제의 CPU관리, CPU 스케줄링


4. 운영체제를 알아야하는 이유
	- 작업 관리자에 들어가보면 여러가지 프로세스가 실행중이다.

	- 여러 프로그램이 실행하고 있을 때, 특정 자원을 우선적으로 실행시켜주는 것을
		=> {동기화} 라고한다.

	- 프로세스들이 동시다발적으로 실행되면 자원을 서로 요구하는데
		=> 이걸 운영체제가 제어해서 자원을 덮어 쓰지 않도록 자원을 보호해준다 관리해준다.
		=> 시스템 호출이라고도 한다.

		ex) 응용 프로그램이 하드디스크에 정보를 저장하려고 한다.
			=> 이 때 운영체제가 중재해서 정보를 저장하게 도와준다.
			=> 직접 접근하는 것이 아니다.
		
	- 운영체제는 어떻게 자원을 효율적으로 관리할지 결정한다.
		- CPU 
		- 프로세스
		- 메모리
		- 파일 시스템 등등..

	- 운영체제란 안전장치라고 생각한다.
	- 운영체제란 프로그램을 위한 프로그램이다.
		=> 이용자를 위한 프로그램이 아니다.
			=> 이용자가 어떤 짓을 할지 모르기 때문에 자원관리를 직접 맡기지 않는다.

	- 오류 메세지도 운영체제에서 보내는 메세지이다.
		=> 프로그램을 관리하는 운영체제에서 깊게 이해하면
		=> 프로그램을 더 잘 이해하고
		=> 문제 해결능력을 키울 수 있다.






		Actor->상속 
		플레이어->무기(소유)

		1. 마우스 포인터 1순위 
		2. 플레이어 -> 무기 계산 (--> 무기) 2순위 방향, 각도
		3. 무기  순위
