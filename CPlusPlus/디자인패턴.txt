


== 디자인패턴 == 
 - 코딩 스타일이 비슷한 부분을 규격화한 것


 == 종류 == 
 - 퍼사드 : 클래스로 기능을 분리한 것들을 관리해주는 구조
 - 프로토타입 : 객체를 복사해서 반환해주는 구조
	- 캐쉬적중률이 높은 강한복사

 - 추상 팩토리 : 부모클래스가 자식클래스에게 인터페이스를 제공하며 호출은 부모에서 하는것
 - 팩토리 메서드 : 부모 클래스가 제공해주는 인터페이스로 구현되는게 다름

 == Solid 5원칙 ==
 1. 단일 책임 원칙 (Single Responsiblity Principle)
	- 특정 클래스에서 연관된 기능은 최대한 줄인다.
	- 결합도 : 의존 관계의 정도
	- 응집도 : 클래스가 필요한 기능을 자신이 가지고 있는것

 2. 개방-폐쇄 원칙 (Open Closed Principle)
	- 확장에는 열려있고 변경에는 닫혀있다 << 추가는 적극반영하되 변경은 최소
	- 확장의 좋은 예시는 virtual

 3. 리스코프 치환 원칙 (Liskov Substitution Principle)
	- 부모 / 자식 관리하는 방식, 그리고 동작이 정상작동되야함

 4. 인터페이스 분리 원칙 (Interface Segregation Principle)
	- 기능은 작게 분리해서 써라

 5. 의존 역전 원칙 (Dependency Inversion Principle)
	- 부모의 인터페이스를 받아서 쓰는 것
	- Level0은 Level1을 알아서는 안된다.
	- 추상화를 의존해야한다 << Virtual 써라.
